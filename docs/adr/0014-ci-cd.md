# ADR-0014: CI/CD with GitHub Actions

- **Status**: Accepted
- **Date**: 2026-10-31

## Context

Code is produced by agents and approved by a single maintainer: CI is the objective guarantee of quality. The project must cost nothing in infrastructure (ADR-0002, ADR-0015). A public GitHub repository gets unlimited CI minutes on standard runners and free security tooling.

## Decision

- Code hosted on **GitHub**, in a **public repository** (organization `cabane3d`).
- CI/CD with **GitHub Actions**.

**On every PR:**
1. pnpm install with caching; Turborepo limits work to affected packages;
2. lint, typecheck, dependency-cruiser, knip;
3. unit, property-based and import corpus tests, with a coverage threshold;
4. Playwright E2E in Chromium, sharded, with reports and traces as artifacts;
5. Electron Linux build + `@electron` scenarios under xvfb;
6. factory checks (ADR-0012): acceptance tests unchanged since the "red tests" commit, and every scenario identifier implemented;
7. security: **CodeQL**, **dependency-review-action**, **gitleaks**;
8. **licenses**: every dependency is compatible with AGPL-3.0 (ADR-0001);
9. commit format check (**Conventional Commits**);
10. **maintainer approval required** (branch protection).

**Nightly:** Stryker, the full visual suite, and the Windows build + smoke test.

**Release:**
- **release-please** computes the version and changelog from Conventional Commits, then creates the release;
- job matrix on **ubuntu** (AppImage, `.deb`) and **windows** (NSIS installer + portable); `electron-builder --publish` uploads binaries and **electron-updater** metadata to the GitHub Release;
- **smoke tests** of the installers (install, launch, check a window opens, quit) **before** the release moves from draft to published;
- **SBOM** (syft) attached to the release.

**Maintenance:** **Renovate** opens dependency update PRs, prioritizing Electron (security fixes). These PRs go through the same pipeline.

## Alternatives considered

- **GitLab CI / Forgejo Actions**: good quality, but fewer free minutes or a self-hosted runner to operate.
- **Changesets** instead of release-please: better suited to monorepos publishing several npm packages; here a single product is released.
- **Dependabot** instead of Renovate: simpler, but less configurable (grouping, scheduling, automerge).

## Consequences

**Positive**
- Zero cost as long as the repository is public.
- Fully automated releases, verified before publication.
- Agent PRs are held to the same standards as the maintainer's.

**Negative / risks**
- Limited concurrency on free runners: pipelines may occasionally queue.
- **The repository must stay public**: a private repository would lose unlimited minutes (Windows counts double, macOS ten times).
- Dependency on GitHub; workflows remain largely portable to Forgejo Actions.
